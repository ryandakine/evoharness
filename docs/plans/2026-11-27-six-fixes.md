## WP4. Scoring (half a day)

1. `numeric_match(answer, reference, rel_tol=1e-6)`: last number on each side (`$1,234.50`, `18.0`,
   units, leading minus), compared as floats; falls back to `exact_match` when the reference has no number.
2. `RunResult` gains `input_tokens` and `output_tokens`; `run_genome` sums them.
3. `Evaluator.score_detail(g, sample) -> list[TaskScore]` (per task: score, calls, tokens in/out,
   seconds). `score()` is rebuilt on it and returns the same numbers as today.
4. `majority_vote(..., sample_base=0)` returns per-task results too, and draws samples
   `sample_base .. sample_base+k-1`, so separate runs don't reuse each other's cached answers.
5. `bootstrap_ci(per_task_scores, seed)` and `paired_bootstrap(a, b, seed)` over tasks, pure Python,
   seeded. Repeats on the same question are averaged per question first: the question is the unit.
6. `llm_judge_scorer(backend, judge_model, rubric)`: 0–1 score, strict output format, unparseable
   output scores 0 and is counted. Never a default; not used by WP1. (Both reviewers suggested
   deferring it; kept because Ryan asked for all six, built last in this package.)
- **Tests:** numeric table; token sums; `score()` unchanged on MockBackend; two `majority_vote` runs
  with different `sample_base` make distinct calls; bootstrap determinism; judge scorer on
  well-formed, malformed and out-of-range replies.

## WP1. Benchmark (1 day build + overnight runs)

**Question:** does any swarm beat a single model, and at what cost?

- **Data:** GSM8K test split (numeric answers), 250 questions sampled with seed 0, stored as
  `benchmarks/gsm8k/tasks.jsonl` with the source sha256 and the sampling script. Stated limit:
  models have likely seen GSM8K, so absolute scores are inflated; only the comparison between arms counts.
- **Split (fixed, in the file):** 30 search / 20 select / **200 test**. Every arm is reported on the
  same 200 test questions. Nothing about the 200 is looked at before all arms are final.
- **Headroom check, on the 50 development questions only:** if the single agent scores above 90%
  there, the base model becomes `llama3.2` (3B). Decided once, recorded, before any test run.
- **Base model:** `ollama/qwen3:8b`. Temperature 0.7, max tokens fixed, one run per arm.
- **Arms**

  | Arm | What | Calls / question |
  |---|---|---|
  | A | single agent | 1 |
  | B3, B5 | majority vote over 3 and 5 samples of the base model (B3 = first three of B5's) | 3, 5 |
  | C | `committee`, base model | 4 |
  | D | `debate`, base model | 4 |
  | E | `mixed`: solvers `qwen3:8b`, `llama3.2`, `qwen3.5-abliterated:9b`; judge `deepseek-r1-abliterated:8b` | 4 |
  | F (phase 2) | NSGA-II graph: searched on the 30, one Pareto candidate picked on the 20, frozen, then scored on the 200 | varies |

  Phase 2 runs only after A–E are published; its search calls are reported as a separate cost line.
- **Cost reporting, no "matched cost" claim:** per arm, calls, input tokens, output tokens and
  wall-clock seconds per question, and the models used. The write-up calls it an accuracy–cost table.
- **Precision, stated up front:** at 80% accuracy, 200 questions give about ±5.5 points on one arm.
  Differences between arms use the paired bootstrap on the same questions. A difference whose
  interval includes zero is reported as "no difference shown".
- **Sample IDs:** each arm gets its own base (`A=0, B=100, C=200, …`) so no arm reuses another's cached reply.
- **Cache:** `benchmarks/gsm8k/cache-<hash>.jsonl`, git-ignored, where the hash covers temperature,
  max tokens, and each model's digest from `ollama show`. Changing any of them starts a new cache.
- **Budget:** priced models are refused unless `--budget-usd` is above zero. Unpriced local models run
  with no budget object (`CachedBackend(budget_usd=0)` would block the first call: `spent >= budget`).
- **Runner:** `benchmarks/run.py`. `--arms`, `--limit N`, `--split dev|test`, `--parallel`. Runs arm by
  arm; inside E, model by model (each solver as a one-node graph first, so the committee run finds
  solver replies in the node cache and Ollama swaps models four times, not 800). Prints an ETA after
  the first 10 questions.
- **Output:** `results.json` and `RESULTS.md` (table, intervals, paired differences vs A and vs B5,
  command, model digests, date, commit). README gets a short "Does it work?" section quoting the
  table whatever it says.
- **Tests (MockBackend, 8 fake tasks):** every arm yields a row; a second run makes zero new calls;
  a priced model without `--budget-usd` is refused; arms don't share sample IDs; test-split rows are
  refused before the dev decision file exists.
- **Verify:** `--limit 5 --split dev` on the rig, then the dev run, then the test run.
- **If the ETA for the test run is over 12 hours:** drop B5 to B3 first, then cut the test set to 150, and say so.

## WP3. Confine the bash tool (1 day)

Threat: text in a repo being audited tells the model to read `~/.ssh` or send data out.

- `ExecutionContext` gains `sandbox` (`bwrap` | `none`), `read_only` and `allow_net`.
- `bwrap` launch, `shell=False`: `["bwrap", …, "--", "/bin/bash", "-c", command]` with
  `--unshare-pid --unshare-ipc --unshare-uts --die-with-parent --new-session`, `--unshare-net` unless
  `allow_net`, `--proc /proc --dev /dev --tmpfs /tmp`, read-only binds of `/usr /bin /sbin /lib*`,
  a short list of `/etc` files (resolv.conf, hosts, passwd, group, ssl, alternatives, ld.so.*),
  read-only binds of `sys.prefix`, `sys.base_prefix` and PATH directories that exist (so a venv or a
  mise-installed Python still runs), the workspace bound read-write or read-only, `--chdir` to it,
  `--clearenv` plus the already-sanitized environment, `HOME=/tmp`.
- Read-only nodes get `PYTHONDONTWRITEBYTECODE=1` and `PYTEST_ADDOPTS=-p no:cacheprovider` so tests
  run without writing into the workspace.
- The probe runs lazily, the first time bash is requested: `bwrap --ro-bind / / true`. A missing or
  blocked bwrap means bash is refused unless `--sandbox none` was passed; the file tools still work.
- A workspace of `/` or `$HOME` is rejected for bash. Documented: everything inside the workspace is
  readable by the model.
- `audit` preset: researcher and verifier read-only, no network; MCP tools are off in a confined run
  unless `--allow-mcp`, because they run outside the sandbox.
- The audit log records sandbox mode, read-only and network per call.
- Rollback is `--sandbox none` per run; reverting the PR is the only way back to unsandboxed-by-default.
- **Tests:** argv builder unit tests (no bwrap needed); integration tests skipped without a working
  bwrap, using a fake HOME with a dummy `.ssh/id` file: reading it fails; writing outside the
  workspace fails; read-only workspace write fails; network unreachable; `git status`, `python -c`,
  and `pytest` on a tiny fixture project pass; timeout still kills the process tree; probe failure refuses bash.
- **Verify:** integration tests on the rig; `bin/swarm audit` on a scratch repo.
- **Out of scope:** macOS and Windows sandboxes, per-command allowlists, seccomp filters.

## WP5. Optimizers carry tools; faster evaluation (1 day)

1. `run_genome`: when `node_tools` is None and `g.tools` is set, use `g.tools`. Meaning of values is
   written down and tested: `g.tools is None` → node rule comes from the caller; a node's `[]` → no tools.
   The node cache key includes the node's allowed tools.
2. Tools travel with their node: `crossover` takes a node's tools from the same parent as its role and
   model (both parents must agree on `tools is None` or it raises); `g_decode` reorders tools with the
   nodes; `GraphDistribution` gains a `tools` field copied into `sample()`/`threshold()`;
   `evolve`/`random_genome` take an optional per-node tool table. (`jfk_scores` already keeps tools via `copy()`.)
3. `Evaluator` takes `tool_registry`, `context`, `max_tool_turns`, also used by `attribute()`.
   Any mutating tool in play requires `allow_mutating=True`.
4. `Evaluator.task_workers` (default 1): tasks of one genome scored in threads, results combined in
   task order. Refused when a mutating tool is in play. `task_workers × max_workers` is capped.
   `CachedBackend` budget: the check-and-reserve happens under the lock, so concurrent calls can't
   pass the cap by more than one call's cost; tested with threads.
- **Tests:** tools survive crossover, decode and sampling (random genomes); `g.tools` is enforced by
  `run_genome`; parallel equals sequential on MockBackend with explicit `model_names`; mutating guard;
  concurrent budget test.
- **Verify:** `examples/run_methods.py` output identical before and after with `task_workers=1`.
